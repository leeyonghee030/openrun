# OpenRun 이슈 계획

> 이 파일이 이슈 계획의 **원본**이다. 계획이 바뀌면 이 파일을 먼저 고치고, GitHub 이슈 본문을 같은 내용으로 맞춘다.
> 상세 이슈는 **그 주차 시작 직전에** 쓴다. 먼 주차는 한 줄만 두고, 가까워지면 구체화한다. (미리 쓰면 계획이 바뀌어 다시 써야 한다)

## 0. 운영 규칙

| 항목 | 규칙 |
|---|---|
| 개발 시간 | 평일 하루 2시간, 주말 하루 최소 4시간 = **주 18시간** (2026-11-02 기준) |
| 이슈 단위 | 주차별 작업 단위. 2~5시간짜리. 너무 잘게 쪼개지 않는다 |
| 시간 칸 | "예상(h)"는 처음 추측이다. 끝나면 "실제(h)"를 적고, 차이가 크면 뒤 이슈의 예상을 고친다 |
| 제목 | Conventional Commits 형식. 예: `feat: 가게 목록·상세 조회 API` |
| 라벨 | `feat` `fix` `chore` `test` `docs` 중 하나 |
| 마일스톤 | 주차마다 하나. 예: `2주차` |
| 브랜치 | `feature/이슈번호-설명`. 예: `feature/4-store-api` |
| 닫기 | PR 본문에 `Closes #이슈번호`를 쓰면 머지될 때 이슈가 자동으로 닫힌다 |
| 상태 칸 | 대기 / 진행 / 완료 / 취소 |
| LLM 활용 | **LLM이 써도 되는 것**: 설정 파일, 더미 데이터, DTO 등 반복 코드. **직접 쓰는 것**: 엔티티, 서비스 로직, 채번, 예외 변환, 핵심 테스트 케이스 |

**계획을 바꾸는 방법:** 이 파일에서 해당 이슈의 시간, 체크리스트, 상태를 고치고, 맨 아래 "변경 이력"에 한 줄 남긴다. 그다음 GitHub 이슈 본문을 수정한다. (Claude에게 "2-4 예상 4시간으로"처럼 말하면 파일을 고치고 붙여넣을 본문을 다시 준다)

## 3. 가정과 열린 질문
- 2주차에는 로그인이 없다. 로그인 틀은 3주차 JWT와 겹쳐서 이슈에서 뺐다.
- 탈퇴, 취소, 호출, 입장, 노쇼는 6주차 이후다.
- 테이블 생성 방식은 2-1에서, 테스트가 개발 DB를 건드리지 않는 방법은 2-3에서 확정한다.
- 가게 목록의 노출 조건(ERD는 접수 `OPEN`까지 포함, API 명세는 승인됨만)은 2-4에서 정한다.
- 가게 공지 문구(P-8)는 Optional이다. 하기로 하면 `stores`에 컬럼을 추가한다 (`03-ERD.md` 수정).
- 시간 추정은 처음이라 틀릴 수 있다. 2-1 이후 "실제(h)"로 보정한다.

## 3-1. Optional 후보 (Core 1~8주차 완료 후, 속도를 보고 결정)

선정 기준: OpenRun의 간판인 "동시성 비교 실험 + 대기열 정확성"을 강화하는 것만 넣는다.
팀프로젝트(굿즈 플랫폼)와 겹치는 기능(결제, 경매, 선착순 정원 이벤트)은 넣지 않는다.
LLM 원칙: 계산과 판단은 코드가, 문장 생성만 LLM이 한다. 대기번호 채번 등 정확성이 필요한 곳에는 LLM을 쓰지 않는다.

| ID | 후보 | 이유 | 난이도 | 결정 시점 |
|---|---|---|---|---|
| O-1 | 예상 대기 시간 ("내 앞 N팀, 약 M분") | 작고 효과가 큼 | 낮음 | 6주차 |
| O-2 | Redis Sorted Set 대기열 버전 + MySQL과 속도 비교 | 5주차 비교 실험 강화 | 중간 | 5주차 |
| O-3 | Redis-MySQL 정합성 검증 배치 | 캐시와 원본 불일치 감지·복구 | 중간 | O-2 이후 |
| O-4 | 호출 건너뛰기/뒤로 미루기 | 순서 정합성 문제로 동시성 이야기 확장 | 중간 | 7주차 |
| O-5 | k6 혼합 시나리오 (등록+조회+호출) + 결과 그래프 | 실험 증거 강화 | 낮음 | 4주차 |
| O-6 | Actuator + Prometheus + Grafana 대시보드 | 락 방식별 비교를 눈에 보이게 | 중간 | 5주차 이후 |
| O-7 | CI에서 동시성 테스트 자동 실행 | 11주차 CI 계획과 연결 | 낮음 | 11주차 |
| O-8 | 가게 운영 요약 리포트 (LLM) | 시간대별 팀 수, 노쇼율을 문장으로 요약 | 중간 | Core 이후 |
| O-9 | 혼잡도 예측 코멘트 (LLM) | 계산은 SQL, 문장만 LLM | 중간 | Core 이후 |
| O-10 | 가게 공지 문구 도우미 (LLM) | 기존 P-8과 연결 | 낮음 | P-8 결정 시 |
